# 0526 故障任务

## 目标

在 `GZ_0524` 平台当前版本中，用“放置分层故障注入组件 -> 绑定目标 -> 配置参数 -> 初始化仿真 -> 运行并查看示波器”的流程完成 3 个独立故障任务，并在单故障完成后进行组合注入验证。

当前闭环模型包：`app/public/model-packages/evtol_closed_loop_fault_demo.json`

## 公共流程

1. 导入闭环模型包。
2. 从左侧“故障组件”放置对应分层注入组件。
3. 点击注入组件上的“绑定目标”。
4. 选择高亮的模块或 CAN/协议连接线。
5. 在绑定弹窗中选择关联变量/报文、数学模型和参数。
6. 确认绑定后，平台生成故障标签和 `faultInstances` 记录。
7. 设置仿真时长 `4s`、步长 `0.1s`，初始化并运行。
8. 打开 `node-scope` 示波器观察 1-3s 故障窗口内的实际波形和参考波形差异。

## 运行逻辑与 Python 绑定结论

当前 3 个 0526 故障任务不需要再手动绑定新的 Python 文件。闭环模型包已经携带 `command_shaper.py` 的源码、接口解析结果和模块绑定信息；平台导入模型包时会恢复模块、连接线、Python 绑定、协议报文字段和 `faultSlots`。故障注入绑定的是模块或连接线声明出来的变量/槽位，运行时通过 `faultInstances` 在仿真值流中叠加偏差、卡死或篡改行为。

只有两种情况需要重新绑定 Python 文件：新增一个真正由 Python 函数实现的仿真模块，或替换已有模块的函数源码/接口。单纯配置故障模型、保存故障任务、加载已实现任务，不需要绑定 Python 文件。

2026-06-03 补充：当前前端演示仍不是完整 Python 解释器；如果没有真实后端，平台会使用本地演示执行器读取绑定源码中的简单赋值表达式。`command_shaper.py` 这类控制整形函数现在会按源码执行 `max/min` 限幅，并把输出和中间变量写回仿真块。后续接入 `runtime/python-backend` 后，应由后端执行任意 Python 模块，前端只保留同一套 payload 和结果映射。

本次同时打通了示波器观测链路：示波器不再直接读取源节点输出，而是读取“经过入边传输后的信号”。因此协议层 `dropout / interrupt / packet_loss` 会在示波器样本中产生 `dropped` 标记，波形绘制时断线；`tamper / delay` 等协议行为也会先作用于连线数据，再进入示波器或下游模块。

## 故障模型保存与加载

本版将顶部原“注入故障”入口改为“加载故障模型”。导入包含模块和连线的系统模型后，该按钮可打开 0526 故障任务加载器：

1. 可直接选择 `陀螺仪零偏`、`单电机卡死`、`控制指令篡改` 或 `组合注入展示`。
2. 选择任务后，平台会自动创建对应分层故障注入组件，绑定目标节点/连接线，并写入 `faultInstances`。
3. “保存当前故障模型”会把当前系统模型、故障实例、故障标签和运行配置打包保存到浏览器本地存储。
4. “加载已保存模型”会恢复最近保存的故障模型包；导出的系统模型包也会携带 `faultInstances`，再次导入后可继续仿真和查看示波器。

旧故障库直接注入列表在这一版不再作为入口展示；隐藏面板内容会被清空，避免误以为仍可通过故障库直接注入。

## 任务 1：陀螺仪零偏故障

| 项目 | 设置 |
| --- | --- |
| 注入组件 | 电气层注入 |
| 绑定目标 | `node-imu`，IMU 陀螺仪反馈 |
| 绑定对象 | `测量角速度` |
| slot | `electrical:测量角速度` |
| 数学模型 | 偏差模型 `bias` |
| 参数 | `bias = 5`，`start = 1`，`duration = 2` |
| 示波器 | `node-scope`，CH2 |
| 预期现象 | 1-3s 内 IMU 反馈通道相对参考波形出现明显偏移 |

实现路径：

1. 放置 `electrical_fault_injector`。
2. 绑定到 `node-imu`。
3. 选择 `测量角速度`。
4. 选择 `bias`，参数填写 `{ bias: 5, start: 1, duration: 2 }`。
5. 运行仿真并打开 `node-scope`，检查 CH2 的故障窗口差异。

## 任务 2：单电机卡死故障

| 项目 | 设置 |
| --- | --- |
| 注入组件 | 物理层注入 |
| 绑定目标 | `node-motor-1`，1号电机与旋翼 |
| 绑定对象 | `motor_max_output` 对应的 1号电机最大输出 |
| slot | `physical:motor_max_output` |
| 数学模型 | 卡死模型 `freeze` |
| 参数 | `mode = zero`，`value = 0`，`start = 1`，`duration = 2` |
| 示波器 | `node-scope`，CH2 |
| 预期现象 | 1-3s 内 1号电机输出被卡到 0，下游动力学和 IMU 反馈出现偏差 |

实现路径：

1. 放置 `physical_fault_injector`。
2. 绑定到 `node-motor-1`。
3. 选择 `1号电机最大输出`。
4. 选择 `freeze`，参数填写 `{ mode: "zero", value: 0, start: 1, duration: 2 }`。
5. 运行仿真并打开 `node-scope`，检查 CH2 的故障窗口差异。

说明：平台同时支持 `mode = hold`，表示保持故障开始前最后一个有效值。本任务采用 `mode = zero`，使电机卡死现象更明确。

## 任务 3：控制指令篡改

| 项目 | 设置 |
| --- | --- |
| 注入组件 | 协议层注入 |
| 绑定目标 | `edge-shaper-error`，指令整形到误差求和之间的 CAN 报文链路 |
| 绑定对象 | `cmd.pitch.shaped` |
| slot | `protocol:edge-shaper-error:can` |
| 数学模型 | 篡改模型 `tamper` |
| 参数 | `scale = 1.5`，`bias = 0`，`start = 1`，`duration = 2` |
| 示波器 | `node-scope`，CH2 |
| 预期现象 | 1-3s 内整形指令在协议链路上传递时放大 50%，闭环反馈出现偏差 |

实现路径：

1. 放置 `protocol_fault_injector`。
2. 绑定到 `edge-shaper-error` 连接线。
3. 选择 `cmd.pitch.shaped`。
4. 选择 `tamper`，参数填写 `{ scale: 1.5, bias: 0, start: 1, duration: 2 }`。
5. 运行仿真并打开 `node-scope`，检查 CH2 的故障窗口差异。

## 组合注入

组合验证按以下顺序建立 3 个绑定：

1. `node-imu` + `electrical:测量角速度` + `bias`
2. `node-motor-1` + `physical:motor_max_output` + `freeze`
3. `edge-shaper-error` + `protocol:edge-shaper-error:can` + `tamper`

组合注入后，平台应存在 3 条 `faultInstances`，并且 `node-scope` 的故障波形相对参考波形在 1-3s 内出现叠加偏差。

## 平台调整记录

1. 分层注入模型别名补全：`bias/dropout/delay/drift/step/degradation/random/stale` 现在会映射到仿真运行时可执行行为。
2. 卡死模型语义补全：`freeze` 支持 `mode = hold` 保持故障前最后值，也支持 `mode = zero` 直接置零。
3. 篡改模型参数规范化：协议层 `tamper` 默认使用 `scale/bias/start/duration`，避免界面显示 `value/mode` 但运行时无法表达 50% 篡改。
4. 指令整形链路协议化：`edge-shaper-error` 已补齐 CAN 元数据和协议故障槽，协议层故障对象明确为“连接线传递的数据”。
5. 故障模型持久化：`faultInstances` 现在会随工作台快照、系统模型包导出和模型包导入一起保存/恢复。
6. 顶部入口调整：旧“注入故障”按钮改为“加载故障模型”，用于加载 0526 已实现任务、保存当前故障模型和加载已保存故障模型。
7. 回归测试补充：已覆盖三项单故障注入、组合注入、示波器采样差异、协议连接线绑定、故障实例导入导出和 0526 任务加载器。
8. Python 绑定演示补齐：无后端时可执行简单源码表达式，`command_shaper.py` 的整形输出不再退化成通用 mock。
9. 协议间断观测补齐：示波器采样经过连线传输，协议丢包/中断会生成 dropped 样本并在波形中断开。
