# GZ_0524 重构路线图

## 目标

本轮重构的目标不是单纯美化属性面板，而是把故障注入平台从“前端拼接状态”整理成“模型包声明驱动”的架构：

- 每个模块有哪些输入、输出、中间变量、参数，由模型包明确声明。
- 故障设置界面只展示当前模块真实拥有的变量和参数。
- 故障实例绑定对象使用模块变量原名，不再生成展示名后反向推断。
- 故障类型必须通过层级、目标类型、插槽和模块能力校验后才能注入。
- Python 后端执行、故障场景保存、故障传播逻辑都应有稳定接口。

## 阶段计划

### P0：契约收敛

- 定义故障类型、故障实例、场景、模块能力的 schema。
- 为模型包补齐 `faultCapabilities`、`inputs`、`outputs`、`intermediates`、`parameters`。
- 增加模型包校验脚本，构建前阻断非法故障绑定。
- 将 UI 中的派生逻辑迁移到统一 selector/service。

### P1：真实运行链路

- 实现 Python 后端执行服务。
- 前端对接真实 `/api/python-flow/execute`。
- 明确执行超时、错误日志、依赖路径和结果回传格式。
- 禁止生产路径静默 fallback 到 mock 结果。

### P2：故障场景与传播

- 建立故障场景保存、加载、启停和撤销接口。
- 引入注入矩阵、传播矩阵和输出矩阵的运行时数据结构。
- 让故障实例可以跨模块传播，但必须保留显式来源和传播路径。

### P3：界面与工具拆分

- 继续按 IBM Carbon 风格压缩属性面板密度，减少大字、厚分隔和重复按钮。
- 将故障设置改为可扫描的变量表，支持批量勾选层级和快速筛选。
- 把旧的 demo/runtime 临时代码拆入 `legacy` 或 `runtime`，避免业务代码和演示代码混杂。
- 增加 Playwright 视觉回归截图，覆盖属性面板、故障库、仿真运行主流程。

## 验收门槛

- `npm test -- --run` 通过。
- `npm run build` 通过。
- `npm run audit:ui` 通过。
- 选择任意模块时，故障设置界面只显示该模块声明过的变量、端口和参数。
- 注入故障后，实例中的绑定对象名称与模型包变量名一致。
- 不兼容故障不能被注入到当前模块。
